## 인증 vs 인가
인증 (Authentication) : 사용자가 누구인지 확인하는 과정, 로그인 과정

인가 (Authorization) : 인증된 사용자가 특정 리소스에 접근할 수 있는지 확인 과정
-> 사용자 역할 (Role) , 권한(Authority) 에 따라 접근 제한

## 로그인은 RESTful API 설계 원칙에 따라 POST 요청을 사용한다. 
* @PostMapping("/login") 이 일반적인 방식이다
* id, pw 를 바디에 담아서 보내기에 안전함
* 로그인은 세션 생성, 토큰 발급 등의 상태 변경 작업이 포함되어있어 POST가 적절하다 

* Get 요청은 캐싱이 될 수 있으며, post 요청은 캐싱되지 않기에 로그인 정보가 캐시에 저장될 위험이 없다. 


## JWT 구조 (Json Web Token)
클라이언트와 서버간의 인증, 정보교환을 위해 사용되는 토큰
세션 정보를 서버에 저장하지 않고, 토큰 자체에 정보를 포함하여 인증을 처리하는 Stateless 방식으로 동작
* Header(헤더) : 토큰의 타입과 해싱 알고리즘을 명시 
* Payload(페이로드) : 사용자의 정보와 클레임 데이터 포함
* Signature(서명) : 헤더와 페이로드를 비밀키로 서명하여 생성된 값

## JWT 토큰 생성 => JwtTokenProvider.java
### JWT Builder 가 헤더와 서명은 자동으로 생성, JWT 페이로드와 서명 키만 지정해주면 된다. 

### Stateless (무상태) 방식
서버가 클라이언트의 상태를 유지하지 않는 방식을 의미 
각 요청은 독립적이며, 이전 요청과 관계없이 처리된다! 


## JWT 사용자 인증 검증 로직 순서
1. 사용자는 /login 으로 아이디와 비밀번호를 입력하여 POST 요청
2. 서버에서 사용자를 인증한 후, jwt 토큰을 생성하여 반환한다. 
3. 사용자는 로그인 후에, API 요청시  Authorization : Bearer <JWT> 헤더를 포함하여 요청 
4. `JwtAuthenticationFilter` 에서 요청을 먼저 인터셉터해서 JWT 토큰 추출한다.  
5. 추출한 토큰을 검증 (유효성, 서명 확인 등)을 한다. 
   6. 검증 성공하면 사용자 인증정보를 스프링 시큐리티 컨텍스트에 저장한다. 
   7. 검증 실패하면 요청은 예외 처리 단계로 넘어간다. 
   8. 만약 인증 실패 혹은 인증되지 않은 요청 발생시 `jwtAuthenticationEntryPoint` 호출되고 여기서 401 에러 반환
9. 인증성공 후 요청 처리

## JWT 로그인 구현시
   * jwt 토큰 생성, 토큰 검증하는 `jwtProvider` 생성
   * API 요청시 jwt 맞는지 확인위해 `jwtFilter` 생성
   * 필터를 `SecurityConfig` 에 설정
   * 로그인 API 생성

## OncePerRequestFilter
OncePerRequestFilter 는 Spring Security 에서 제공하는 필터 클래스
1번 요청당 1번만 실행되는 필터를 만들 때 사용된다.
일반 필터는 동일한 요청 내에서 여러번 실행될 수 있다. 
하지만 JWT 인증 필터는 한 요청에 한번만 실행되야하기에 상속받음!

## Filter 란
Spring 에서 Filter 란 HTTP 요청, 응답을 가로채서 특정 로직을 실행하는 컴포넌트

즉, 클라이언트가 서버에 요청을 보냈을 때 컨트롤러가 처리하기전에 실행되는 로직을 추가할 수 있다!

* Spring Boot 에서 `@Component` 를 사용하면 자동으로 필터를 등록할 수 있음

### 해당 코드가 필요한 이유

```
if (ObjectUtils.isEmpty(authHeader) || !authHeader.startsWith(BEARER)) {
   filterChain.doFilter(request, response);
   return;
}
```

* Spring Security 의 필터 체인에서 JWT 인증 필터는 모든 요청을 가로챈다. 
* 하지만, 모든 요청이 jwt 인증을 필요하는것 아님 -> 로그인, 회원가입, 공개 API
* jwt 가 없는 요청도 정상적으로 처리되려면 `filterChain.doFilter(reqest,response);` 를 사용해야한다.

## @EnableWebSecurity
Spring Security 를 활성화하는 애노테이션
SpringBoot 애플리케이션 보안설정 적용할때 사용된다.
Spring Security 기본설정을 변경할 수 있고 추가적으로 보안설정을 할 수 있다. 


`.addFilterBefore(jwtAuthenticationFilter, UsernamePasswordAuthenticationFilter.class) `
스프링 시큐리티 filter Chain 에 UsernamePas~ 보다 jwtAuthenticationFilter를 먼저 실행하도록 함
`UsernamePasswordAuthenticationFilter` => 기본 스프링 시큐리티가 제공하는 필터, 사용자의 username 과 password로 인증처리


## Authentication 객체
Spring Security 에서 현재 로그인된 사용자의 정보를 담고 있는 객체 
즉, 사용자의 아이디,권한 Role 등 인증된 정보를 포함하고 있다
사용자가 로그인을 하면 Spring Security는 Authentication 객체를 생성하여 SecurityContext에 저장한다. 


## 로그인을 성공해도 403 Error 가 떴던 이유 
`UserDetailService` 에서 디비 사용자 조회까지는 잘되었지만 `ROLE_ADMIN cannot start with ROLE_ (it is automatically added)` 에러 발생

```java
      return User.withUsername(user.getUsername())
            .password(user.getPassword()) 
            .roles(user.getRole()) // Spring Security는 자동으로 ROLE_ 을 붙여버림
            .build();
```

DB 에는 ROLE_ADMIN 으로 저장되어있지만, `ROLE_ROLE_ADMIN `으로 되어버려서 오류 발생

## Spring Security 에서 roles vs authorities() 비교
# 🚀 Spring Security `roles()` vs `authorities()` 차이점

| 구분 | `roles()` 사용 | `authorities()` 사용 |
|------|-------------|----------------|
| **설명** | Spring Security가 자동으로 `ROLE_`을 붙임 | `ROLE_` 없이도 직접 권한을 설정 가능 |
| **DB 저장 방식** | `ADMIN` 형태로 저장해야 함 (`ROLE_ADMIN` 저장 시 오류) | `ROLE_ADMIN`, `ADMIN` 등 자유롭게 저장 가능 |
| **사용 사례** | 간단한 권한 관리 (`ROLE_`이 항상 붙는 경우) | 세밀한 권한 관리 (예: `READ_PRIVILEGE`, `WRITE_PRIVILEGE`) |
| **유연성** | 낮음 (`ROLE_`이 자동 추가됨) | 높음 (`ROLE_`이 자동 추가되지 않음) |
| **보편적인 방식** | 🔹 간단한 시스템에서 사용 | ✅ 실무에서 더 많이 사용됨 |

##🚀 Spring Security 로그인 시 비밀번호 비교 과정

Spring Security 는 UserDetailService 를 사용하여 사용자 정보를 조회한다.

비밀번호 비교는 AuthenticationManager가 자동으로 수행한다. 
그래서 비밀번호 비교코드를 작성하지 않아도 SpringSecurity 내부에서 작동을 처리한다. 

##🚀 로그인 흐름
(1) 로그인 요청 시 AuthenticationManager.authenticate() 호출
   * UsernamePasswordAuthenticationToken 를 객체 생성해서 입력한 id, password 전달
   * authenticationManager 가 요청을 받아서 `UserDetailService.loadByUsername()` 을 호출하여 사용자 정보를 조회 
```java
Authentication authentication = authenticationManager.authenticate(
    new UsernamePasswordAuthenticationToken(loginId, password)
);
```
   * `UserDetailService.loadByUsername()` 를 오버라이드하여 Username,password,role 을 반환
     
(2)Spring Security 내부에서 비밀번호 비교 수행
   * Security Config 에 passwordEncoder() 등록하면, Spring Security가 이거를 자동으로 사용해 비밀번호를 비교한다.
   ```java
   @Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder(); // ✅ 비밀번호 암호화 및 비교를 위한 PasswordEncoder 등록
}
   ```
